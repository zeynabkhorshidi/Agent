# Sellora — میز فروش مکالمه‌ای فارسی

نسخه اجرایی توسعه با مسیر کامل سفارش **متنی** و داده کنترل‌شده. طراحی RTL، حالت روشن/تیره، سبد مشترک، احراز آزمایشی، بازیابی سبد، ثبت تراکنشی، PDF فارسی و پنل مدیریت دارد. سرویس صوت، کاتالوگ واقعی و سامانه‌های شرکت هنوز متصل نیستند؛ این تحویل نسخه عملیاتی Voice AI نیست.

## اجرای سریع

Python 3.12 و مرورگر جدید لازم است. از پوشه‌ای که این فایل در آن است اجرا کنید:

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
export SELLORA_ADMIN_PASSWORD='رمز-بلند-اختصاصی-خودتان'
uvicorn sellora.app:app --host 127.0.0.1 --port 8000
```

در مرورگر آدرس محلی پورت ۸۰۰۰ را باز کنید. پنل مدیریت مسیر `/admin` و مستند فنی API مسیر `/api/docs` است. فایل `.env.example` فقط الگوست؛ برنامه آن را خودکار نمی‌خواند. متغیرها را export کنید یا با Compose بارگذاری کنید. رمز واقعی را در مخزن قرار ندهید.

## تجربه سفارش آزمایشی

۱. «با نوشتن شروع می‌کنم» را انتخاب کنید. شماره ساختگی با قالب ۰۹ و یازده رقم وارد کنید.
۲. هیچ پیامکی ارسال نمی‌شود؛ کد آزمایشی **۱۲۳۴۵۶** است. این روش مجوز استفاده از اطلاعات واقعی نیست.
۳. نام، شهر و آدرس ساختگی را به ترتیب وارد و مقصد را با «بله» تأیید کنید.
۴. بنویسید «پرتقال دو کارتن و انبه سه کارتن». تعداد را در سبد هم می‌توانید تغییر دهید.
۵. «نه پرتقال رو سه کارتن کن و انبه رو حذف کن» را امتحان کنید.
۶. مرور سفارش، تیک تأیید نسخه فعلی و ثبت آزمایشی را بزنید. شماره و PDF قابل دریافت‌اند.
۷. خروج امن، ورود با همان شماره و کد آزمایشی، بازیابی سبد نیمه‌تمام و سفارش‌های من را امتحان کنید.

مبلغ‌ها عدد صحیح **تومان** هستند؛ هر کارتن نمونه ۱۲ عدد دارد. پیش‌فرض عمده‌فروشی و حداقل یک کارتن یک فرض قابل تغییر است. مالیات، ارسال، پرداخت و زمان تحویل تعریف نشده‌اند؛ جمع نمایش‌داده‌شده فقط جمع اقلام است. رسید، فاکتور رسمی نیست.

## ساختار

- `sellora/app.py`: API، نشست، احراز آزمایشی، منطق مرحله‌ای مکالمه، سبد، مرور، ثبت و کنترل دسترسی.
- `domain.py`: نرمال‌سازی فارسی و انتخاب محصول قاعده‌ای؛ مدل زبانی نیست.
- `db.py` و `migrations/001_initial.sql`: SQLite با WAL، ذخیره پایدار و migration تکرارپذیر.
- `adapters.py`: قراردادهای صوت، مشتری، تجارت و تلفن؛ Router و Circuit مستقل برای آزمون.
- `receipt.py`: PDF با فونت تعبیه‌شده، شکل‌دهی فارسی، تاریخ شمسی و ساعت تهران.
- `web/`: رابط بدون مرحله build، فونت‌های محلی با مجوز همراه، بدون وابستگی CDN.
- `tests/`: آزمون قواعد و تراکنش‌ها؛ آزمون مرورگر جدا.
- `docs/`: معماری، قراردادها، استقرار و نتیجه واقعی آزمون‌ها.

## آزمون

```sh
python -m unittest discover -s tests -v
```

آزمون مرورگر اختیاری است و به سرور روشن و Chromium نیاز دارد:

```sh
pip install playwright==1.56.0
CHROMIUM_PATH=/usr/bin/chromium python tests/browser_smoke.py
```

این آزمون فقط داده ساختگی می‌سازد. فایل‌های تصویر و PDF در `artifacts/` قرار می‌گیرند. جزئیات آزمون‌های اجراشده در [گزارش](docs/TEST_REPORT.md) آمده است.

## Docker

```sh
export SELLORA_ADMIN_PASSWORD='رمز-بلند-اختصاصی-خودتان'
docker compose up --build -d
docker compose ps
```

داده در volume نگه‌داری می‌شود. این پیکربندی توسعه است و فقط روی loopback منتشر می‌شود. برای پراکسی دارای CA اختصاصی، دستور build امن در [استقرار](docs/DEPLOYMENT.md) آمده است. با `SELLORA_ENV=production` برنامه عمداً اجرا نمی‌شود؛ حذف این حفاظ به‌تنهایی آمادگی عملیاتی ایجاد نمی‌کند.

## وضعیت تحویل

جریان سفارش محلی واقعاً اجرا و آزمایش شده است. برای اتصال واقعی، مستندات و نمونه‌های STT/TTS، OTP و منابع تجاری لازم‌اند. جزئیات و محدودیت‌ها در [قراردادهای اتصال](docs/INTEGRATIONS.md) و [معماری](docs/ARCHITECTURE.md) ثبت شده‌اند. هیچ سرویس موجودی با سرویس خارجی دیگری جایگزین نشده است.
