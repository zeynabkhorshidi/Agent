# Sellora — فروشگاه فارسی و سفارش‌گیری صوتی

نسخه جدید با فونت **ایران‌سنس ارسالی کاربر**، پالت سرمه‌ای/آبی/سفید، صفحه فروشگاه، کاتالوگ مستقل، جزئیات کالا و سبد موبایل بازطراحی شده است. متن و صوت از یک جریان سفارش استفاده می‌کنند؛ مرور و تأیید صریح با صدا نیز پشتیبانی می‌شود.

**مرز داده و اتصال:** تجارت و احراز فعلاً آزمایشی‌اند. STT طبق API شرکت پیاده شده اما دسترسی زنده از محیط ساخت تأیید نشده است. کاتالوگ شرکت نیز از این محیط باز نشده؛ عکس‌های آن وارد نشده‌اند. امکان بارگذاری عکس واقعی و ورود JSON در پنل مدیریت وجود دارد. مدل مکالمه و TTS به پیکربندی سرویس واقعی نیاز دارند؛ بدون آن‌ها، راهنمای محلی و پاسخ متنی فعال‌اند. جزئیات در [نسخه جدید](docs/STOREFRONT_AND_ASSISTANT.md) است.

## شروع سریع در ویندوز

۱. Python 3.12 نصب باشد. ZIP جدید را در پوشه جدا استخراج کنید.
۲. فایل **`start-windows.cmd`** را اجرا کنید. محیط مجازی فقط اگر وجود نداشته باشد ساخته می‌شود؛ وابستگی‌ها نصب و `.env` از الگو ساخته می‌شود.
۳. پس از دیدن `Uvicorn running`، آدرس محلی پورت ۸۰۰۰ را در مرورگر باز کنید:

```text
http://127.0.0.1:8000
```

۴. «بررسی اتصال» را بزنید. بک‌اند روی همین کامپیوتر باید از شبکه شرکت به سرویس توسعه دسترسی داشته باشد. میکروفون روی localhost یا HTTPS کار می‌کند.
۵. «شروع گفت‌وگو و خرید» را بزنید و میکروفون را مجاز کنید. حالت ادامه خودکار، متن نهایی را ارسال می‌کند؛ برای اصلاح پیش از ارسال تیک آن را بردارید. پس از تکمیل مشخصات و سبد، بگویید «همین کافیه»؛ مرور را بررسی و با «تأیید با صدا» و جمله «سفارش را تأیید می‌کنم» ثبت کنید.

راه‌اندازی دستی در PowerShell، از پوشه شامل requirements.txt:

```powershell
py -3.12 -m venv .venv
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn sellora.app:app --host 127.0.0.1 --port 8000
```

اگر `.venv` یا `.env` قبلاً دارید، دستور ساخت/کپی آن را تکرار نکنید. `sellora/app.py` مستقیماً با دکمه Run اجرا نمی‌شود؛ فرمان uvicorn لازم است. **Torch، torchvision، Whisper و FFmpeg روی کامپیوتر Sellora لازم نیستند**؛ پردازش صوت روی سرویس موجود شرکت انجام می‌شود.

## تنظیم اتصال

برنامه `.env` کنار README را خودکار می‌خواند و متغیرهای از قبل exportشده را تغییر نمی‌دهد. نشانی توسعه پیش‌فرض الگو:

```dotenv
STT_BASE_URL=http://172.20.3.81:30089
STT_ONLINE_TIMEOUT=45
STT_OFFLINE_TIMEOUT=120
STT_MAX_UPLOAD_MB=25
```

نشانی از فایل Deploy Address.txt است. پروتکل HTTP بر اساس نمونه uvicorn سرویس انتخاب شده؛ اگر ورودی استقرار HTTPS است، base URL صحیح را در سرور تنظیم کنید. برای اتصال به سرویس عملیاتی شرکت آدرس پایه را به `http://172.20.4.81:30081` تغییر دهید؛ این تغییر داده‌های فروش نمونه را واقعی نمی‌کند. هیچ IP داخلی در JavaScript مشتری وجود ندارد. فایل [اتصال](docs/VOICE_INTEGRATION.md) قرارداد دقیق و عیب‌یابی را توضیح می‌دهد.

حالت Auto/Online/Offline در پنل مدیریت ذخیره و فوراً اعمال می‌شود. Auto در خرابی آنلاین به آفلاین می‌رود؛ سکوت، فایل نامعتبر و خطای مجوز باعث fallback نمی‌شوند. آفلاین بودن STT به معنی آفلاین بودن همه زیرساخت نیست.

## سفارش نمونه

شماره ساختگی ۱۱ رقمی با ۰۹ وارد کنید. **هیچ پیامکی ارسال نمی‌شود؛ کد آزمایشی ۱۲۳۴۵۶ است.** نام، شهر و آدرس ساختگی را به ترتیب بگویید یا بنویسید، سپس مقصد را تأیید کنید.

مثال‌ها: «پرتقال دو کارتن و انبه سه کارتن»، «نه پرتقال رو سه کارتن کن و انبه رو حذف کن»، «توقف»، «ادامه بده»، «از اول»، «همین کافیه». در حالت دستی متن گفتار پیش‌نویس قابل اصلاح است؛ حالت ادامه خودکار آن را به مکالمه می‌فرستد. ثبت نهایی در هر دو حالت به تأیید صریح همان نسخه نیاز دارد. «مرور سفارش» و تأیید نهایی با تیک یا نوبت صوتی معتبر برای ثبت لازم‌اند. PDF فارسی از snapshot پایدار سفارش ساخته می‌شود.

مبلغ پایه صحیح **تومان** است. کارتن ۱۲تایی و حداقل یک کارتن، فرض قابل تغییر نمونه است. مالیات، ارسال، پرداخت و تحویل هنوز تعریف نشده‌اند؛ جمع فقط جمع اقلام است. رسید فاکتور رسمی نیست.

## مدیریت و اجراهای دیگر

در `.env` مقدار اختصاصی `SELLORA_ADMIN_PASSWORD` را تعیین و سرور را دوباره اجرا کنید؛ سپس `/admin` را باز کنید. رمز پیش‌فرض نداریم. `SELLORA_SALES_PASSWORD` و `SELLORA_OPERATOR_PASSWORD` نقش‌های محدودتر را فعال می‌کنند. رمزها وارد مخزن نشوند.

لینوکس: `bash start-linux.sh` یا نصب venv و اجرای همان uvicorn. Docker:

```sh
export SELLORA_ADMIN_PASSWORD='رمز-اختصاصی-خودتان'
docker compose up --build -d
```

داده در volume پایدار است. جزئیات CA پراکسی و گذر به استقرار واقعی در [استقرار](docs/DEPLOYMENT.md) آمده است. `SELLORA_ENV=production` همچنان تا اتصال احراز و تجارت واقعی مسدود است.

## آزمون و ساختار

```sh
python -m unittest discover -s tests -v
```

`tests/test_stt.py` قرارداد HTTP و خطاها را کنترل می‌کند؛ `tests/storefront_browser.py` رابط جدید، تأیید نهایی با میکروفون، مسیر تمام‌صوتی با ارسال خودکار و PDF را در برابر fixture کنترل‌شده می‌سنجد. این‌ها دقت تشخیص Google/Whisper یا دسترسی شبکه شرکت را تأیید نمی‌کنند. راه اجرای تست‌ها و نتیجه واقعی در [گزارش فروشگاه جدید](docs/STOREFRONT_TEST_REPORT.md) است.

- `sellora/stt.py`: Adapter واقعی HTTP مستند، timeout، دو circuit مستقل و fallback.
- `sellora/voice_api.py`: نشست، multipart، محدودیت حجم/نرخ، نتیجه نسخه‌دار و لغو محلی.
- `web/voice.js`: میکروفون، انتخاب دستگاه، ضبط حداکثر ۵۰ ثانیه، فایل، لغو و حذف پاسخ دیررس.
- `sellora/app.py`: ماشین حالت متن و صوت مشترک، سبد، مرور، سفارش و مجوزها.
- `migrations/`: SQLite پایدار، WAL، migrationهای تکرارپذیر ۱ و ۲.
- `sellora/receipt.py`: PDF فارسی تعبیه‌فونت، تاریخ شمسی و ساعت تهران.
- `docs/`: معماری، قراردادهای اتصال، نتیجه آزمون و شواهد.

فایل صوت در Sellora نگه‌داری نمی‌شود؛ صرفاً موقت برای ارسال پردازش می‌شود. نتیجه تبدیل حدود ۱۰ دقیقه برای retry نوبت در DB است و هر ۳۰ ثانیه پاک‌سازی می‌شود؛ رونوشت ارسالی شما تابع سیاست مکالمه است. نگه‌داری داده در خود سرویس STT باید با مالک آن تأیید شود.

## پاسخ طبیعی و صوتی

مدل: `LLM_BASE_URL`، `LLM_MODEL` و در صورت نیاز `LLM_API_KEY` را از سرویس سازگار chat/completions تنظیم کنید. صدا: `TTS_ENDPOINT`، `TTS_MODEL`، `TTS_VOICE` و در صورت نیاز `TTS_API_KEY` را مطابق قرارداد واقعی audio/speech تنظیم کنید. هیچ endpoint TTS روی سرویس Whisper فرض نشده است. نام مدل و صدا دلخواه ساختگی وارد نکنید؛ باید در سرویس شما وجود داشته باشند. بدون این تنظیمات، ادعای فعال‌بودن مدل یا صدای انسانی نمی‌شود.
