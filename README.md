# Sellora

فروشگاه فارسی با فونت ایران‌سنس، تم سرمه‌ای/آبی/سفید، کاتالوگ شرکت، گفت‌وگو، سبد مشترک، مرور، تأیید صوتی و رسید PDF.

**اجرای عادی هیچ کالای نمونه یا عکس عمومی اضافه نمی‌کند.** فقط اطلاعاتی که واقعاً از `https://catalog.sayesaman.com/` دریافت شوند در ویترین قرار می‌گیرند. تصویر اول نیز از محصول سن‌ایچِ همان کاتالوگ انتخاب می‌شود؛ تا دریافت موفق، عکس جایگزین یا ساختگی نمایش داده نمی‌شود.

## اجرا در ویندوز

Python 3.12 لازم است. ZIP را در پوشه جدا استخراج و `start-windows.cmd` را اجرا کنید. پس از نمایش Uvicorn running، در مرورگر باز کنید:

```text
http://127.0.0.1:8000
```

فرمان دستی از پوشه شامل این README:

```powershell
py -3.12 -m venv .venv
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn sellora.app:app --host 127.0.0.1 --port 8000
```

محیط مجازی یا `.env` موجود خودتان را دوباره نسازید یا بازنویسی نکنید. فایل app.py مستقیماً با دکمه Run اجرا نمی‌شود. میکروفون به localhost یا HTTPS نیاز دارد. Torch و مدل Whisper روی کامپیوتر Sellora لازم نیستند؛ صوت به سرویس شرکت ارسال می‌شود.

## کاتالوگ و عکس‌ها

دریافت خودکار فعال است؛ کنترل آن با `CATALOG_AUTO_SYNC` انجام می‌شود. پنل `/admin` نیز دکمه دریافت محصولات و عکس‌ها از سایت دارد. رمز مدیریت را خودتان در `SELLORA_ADMIN_PASSWORD` فایل `.env` تعیین و برنامه را دوباره اجرا کنید. رمز پیش‌فرض وجود ندارد.

در این محیط دسترسی سایت با خطای پراکسی ۴۰۳ مسدود است و کاتالوگ واقعی هنوز دریافت نشده. اجرای Sellora روی شبکه‌ای که سایت را باز می‌کند یا اعمال دسترسی محیط ابری لازم است. اگر پس از دریافت صفحه ساختار داده آن شناخته نشود، مبدل باید بر اساس HTML واقعی همان سایت تکمیل شود؛ ادعای استخراج همه محصول‌ها پیش از مشاهده سایت وجود ندارد.

هیچ بسته‌بندی، تعداد کارتن، قیمت یا موجودی ساخته نمی‌شود. اقلام تا تکمیل اطلاعات تجاری توسط منبع معتبر غیرفعال‌اند. رسید، پرداخت موفق یا فاکتور رسمی شرکت نیست.

## گفتار به متن

در `.env`:

```dotenv
STT_BASE_URL=http://172.20.3.81:30089
STT_ONLINE_TIMEOUT=45
STT_OFFLINE_TIMEOUT=120
STT_MAX_UPLOAD_MB=25
```

مقصد عملیاتی مستند: `http://172.20.4.81:30081`؛ پروتکل ورودی استقرار شرکت باید تأیید شود. backend باید به شبکه مجاز شرکت دسترسی داشته باشد؛ مرورگر به IP داخلی وصل نمی‌شود.

اگر صدا کار نمی‌کند، **`check-voice-windows.cmd`** را اجرا کنید. نتیجه در `data/stt-diagnostics.json` ذخیره می‌شود و هیچ صوت یا اطلاعات شخصی ارسال نمی‌کند. این بررسی خطای نشانی، دسترسی 401/403، شبکه، TLS و ناهماهنگی قرارداد را از هم جدا می‌کند.

ضبط کم‌حجم دیگر خودکار حذف نمی‌شود. در مرورگر پشتیبان، صوت به PCM WAV تک‌کاناله ۱۶ کیلوهرتز تبدیل می‌شود. مسیر مستند STT همان `/api/v1/stt/online` و `/api/v1/stt/offline` با فیلد multipart به نام `file` است؛ Web Speech API جای آن استفاده نشده است.

## سفارش و پاسخ

ابتدا مشخصات و مقصد تکمیل می‌شوند. متن و صوت یک سبد را تغییر می‌دهند. «همین کافیه» مرور را باز می‌کند؛ پس از بررسی اقلام و مبلغ، «تأیید با صدا» و جمله «سفارش را تأیید می‌کنم» فقط همان نسخه سفارش را ثبت می‌کنند. قیمت یا سبد تغییر کند، تأیید تازه لازم است.

اتصال احراز واقعی شرکت، منابع قیمت/موجودی/ERP، مدل مکالمه و TTS هنوز نیازمند پیکربندی واقعی‌اند. کد ۱۲۳۴۵۶ فقط برای احراز توسعه است و پیامک ارسال نمی‌کند؛ با داده واقعی مشتری استفاده نشود. این توضیح مهم از جریان احراز حذف نشده است. `SELLORA_ENV=production` تا اتصال این منابع مسدود است.

برای مدل و صدای پاسخ، متغیرهای LLM و TTS در `.env.example` آمده‌اند. فایل‌های STT شرکت به‌تنهایی مدل مکالمه یا TTS نیستند. جزئیات در docs/STOREFRONT_AND_ASSISTANT.md است.

## آزمون و استقرار

```sh
python -m unittest discover -s tests -v
```

داده مصنوعی فقط در tests/fixtures.py و سرور tests.testing_app است؛ در اجرای عادی وارد نمی‌شود. نتیجه و محدودیت‌های نسخه فعلی در [گزارش اصلاحات](docs/CATALOG_AND_STT_FIXES.md) است. گزارش‌های قدیمی مربوط به نسخه‌های قبلی‌اند.

لینوکس: `bash start-linux.sh`. Docker و volume پایدار در compose.yaml ارائه شده‌اند؛ راهنمای TLS، پشتیبان و استقرار در docs/DEPLOYMENT.md است.
