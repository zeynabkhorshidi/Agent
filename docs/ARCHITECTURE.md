# تصمیم‌های معماری و مرز محصول

نسخه جدید فروشگاه، تأیید شفاهی متصل به quote، Adapter مدل ساختاریافته و TTS اختیاری در [STOREFRONT_AND_ASSISTANT.md](STOREFRONT_AND_ASSISTANT.md) مستند شده‌اند. توصیف مدلِ آینده در بخش‌های قدیمی زیر با این به‌روزرسانی تکمیل می‌شود؛ اتصال واقعی و کیفیت مدل هنوز تأیید نشده است.

به‌روزرسانی صوت: Adapter HTTP اجرایی در stt.py و کانال multipart در voice_api.py افزوده شده است. UI از MediaRecorder استفاده می‌کند و متن نهایی را پیش از ارسال قابل اصلاح نشان می‌دهد. جزئیات جدید در VOICE_INTEGRATION.md است؛ قرارداد TTS هنوز وجود ندارد.

مخزن در شروع فاقد فایل و commit بود. انتخاب: FastAPI، Python 3.12 و وب استاندارد بدون زنجیره ساخت جاوااسکریپت. استفاده از Next.js برای این نسخه کاربرد ضروری نداشت. پایگاه داده SQLite با WAL برای یک نمونه توسعه و تراکنش محلی انتخاب شد؛ ادعای PostgreSQL، چندگرهی یا مقیاس سازمانی وجود ندارد. S3 اضافه نشده چون فایل صوت نگه‌داری نمی‌شود و PDF از snapshot سفارش بازتولید می‌شود.

## جداسازی مسئولیت‌ها

مرورگر ← کانال HTTP و نشست ← ماشین حالت مکالمه ← قواعد دامنه ← سبد/مرور/سفارش ← SQLite.

Adapter اجرایی STT و قرارداد توسعه Telephony مستقل‌اند. مدل آینده فقط درخواست ساختاریافته پیشنهاد می‌دهد؛ ابزارهای سرور هویت، قیمت، واحد، موجودی و مجوز را کنترل می‌کنند. در این نسخه Parser محلی قطعی است؛ محتوای پیام یا محصول به عنوان دستور سیستمی اجرا نمی‌شود. هیچ متن کاتالوگی نمی‌تواند قیمت یا نقش کاربر را تغییر دهد.

موجودیت‌ها: مشتری و مقصد در پروفایل، نشست و وضعیت مکالمه، محصول و SKU، قیمت مستقل، موجودی مستقل، سبد نسخه‌دار، مرور مدت‌دار، سفارش و snapshot اقلام، رویداد ممیزی، رونوشت، رضایت، درخواست تماس، تنظیمات و جدول کمپین. جدول کمپین و رضایت برای توسعه طرح وجود دارند؛ موتور کمپین، ضبط با رضایت و API مربوط هنوز پیاده نشده‌اند. آدرس‌ها فعلاً یک مقصد در پروفایل‌اند؛ انتخاب از چند آدرس نیازمند توسعه است. اقلام سفارش در snapshot پایدارند و تغییر بعدی کاتالوگ رسید را عوض نمی‌کند.

## تضمین‌های ثبت محلی

- هر تغییر سبد revision را افزایش داده و مرور قبلی را باطل می‌کند.
- مرور فقط با هویت آزمایشی، اطلاعات کامل و مقصد تأییدشده صادر می‌شود؛ اعتبار پنج دقیقه است.
- snapshot شامل مشتری، نام، ویژگی‌ها، قیمت، تعداد، جمع و سیاست کارشناس است.
- ثبت با `BEGIN IMMEDIATE`، بازخوانی قیمت/موجودی، بررسی نسخه‌ها و کنترل تغییر مشخصات انجام می‌شود.
- درج سفارش و کاهش موجودی در یک تراکنش است. ناموجودی، تغییر قیمت یا پایان مهلت نیازمند مرور و تأیید جدید است.
- `request_key` و `quote_id` هر دو یکتا هستند؛ retry پس از timeout همان سفارش را برمی‌گرداند، حتی اگر سبد پاک شده باشد.
- پیام متنی «تأیید» به‌تنهایی سفارش ثبت نمی‌کند؛ اقدام نهایی و تیک تأیید نسخه فعلی لازم است.
- وضعیت پرداخت مستقل و در این نسخه نامشخص است. سیاست کارشناس، پیش‌فاکتور «در انتظار تأیید کارشناس» صادر می‌کند؛ گردش تأیید نهایی کارشناس هنوز اتصال ندارد.

## حافظه و دسترسی

کوکی نشست تصادفی، HttpOnly و SameSite=Strict است؛ مشخصات مشتری در localStorage ذخیره نمی‌شود. فقط انتخاب تم ذخیره می‌شود. رونوشت تلفن/کد ماسک می‌شود؛ اطلاعات آدرس در پایگاه توسعه وجود دارد و استفاده از داده واقعی مجاز نیست. هویت آزمایشی قبل از نمایش سابقه لازم است، اما کد ثابت امنیت عملیاتی ندارد. نشست مشتری یک روز اعتبار دارد. خروج آن را منقضی می‌کند. سبد مشتری پس از ورود مجدد آزمایشی قابل بازیابی است. ابزار پاک‌سازی رونوشت مستقل است.

مدیر تنظیمات و قیمت نمونه را تغییر می‌دهد؛ کارشناس فروش سفارش و رسید را می‌بیند؛ اپراتور مشخصات مشتری یا دریافت رسید ندارد. نقش‌ها از رمزهای مستقل محیطی انتخاب می‌شوند، مجوز در سرور کنترل می‌شود و صرف مخفی‌کردن دکمه نیست. نشست مدیریت یک ساعت و در حافظه پردازش است؛ راه‌اندازی مجدد آن را باطل می‌کند. برای عملیات واقعی SSO، نقش‌های فردی، MFA، محدودیت نرخ ورود و ممیزی هویت شخصی لازم است.

## محدودیت‌های مکالمه

مسیر تدریجی موبایل ← کد آزمایشی ← نام ← شهر ← آدرس ← تأیید مقصد ← خرید وجود دارد. محصول گفته‌شده پیش از موبایل نگه‌داری می‌شود. Parser چندقلمی، حذف، تغییر تعداد، توقف، ادامه و شروع مجدد تأییدشده را پشتیبانی می‌کند. «اولی» و «حذفش کن» محدود به سبد و آخرین محصول‌اند؛ ارجاعات پیچیده و جمع‌آوری تمام اطلاعات یک جمله عمومی پوشش کامل ندارند. برای ابهام نام/واحد، سؤال روشن‌کننده مطرح می‌شود. واحد این نسخه کارتن است؛ واحدهای دیگر نیازمند توسعه اعتبارسنجی هستند.

پیشنهاد فعلی یک مکمل قاعده‌ای آزمایشی است، نه آمار محبوبیت یا سابقه خیالی. رد پیشنهاد مانع سفارش نیست. پیشنهاد خرید مجدد، تحلیل فصلی، بودجه، کمپین واقعی، آزمون A/B و معیارهای ریزش هنوز داده/پیاده‌سازی کامل ندارند. تنظیم سبک نگارش برای آینده ذخیره می‌شود؛ متن قواعد فعلی ثابت است.
