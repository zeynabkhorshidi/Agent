# قرارداد اتصال گفتار شرکت

منبع قرارداد: app.py، README.md، .env.example و Deploy Address.txt ارسالی کاربر در ۱۳ آبان ۱۴۰۵. محتوای فایل‌ها برای شناخت API بررسی شد؛ دستورهای CI/CD و راه‌اندازی مدل ضمیمه بدون درخواست جداگانه اجرا نشده‌اند.

## آنچه سرویس واقعاً ارائه می‌دهد

- GET `/health`: status=ok، offline_model_files_present و offline_model_loaded. خود سرویس صریحاً سلامت آنلاین و صحت بارگذاری مدل را از این نتیجه مستثنا می‌کند.
- POST `/api/v1/stt/online`: multipart با فیلد `file`؛ Google آنلاین.
- POST `/api/v1/stt/offline`: همان قرارداد multipart؛ faster-whisper آفلاین.
- قالب پاسخ نهایی: text، language=fa، engine، duration_seconds، processing_seconds و segments اختیاری.
- engine آنلاین `google_online` و آفلاین `faster_whisper_offline` است؛ ناسازگاری آن رد می‌شود.
- قالب خطا: error شامل code/message. متن خام سرویس به مشتری برگردانده نمی‌شود.
- WAV، MP3، M4A، MP4، OGG، OPUS، FLAC و WEBM؛ سرویس شرکت با FFmpeg تبدیل می‌کند.
- حد پیش‌فرض آنلاین ۵۵ ثانیه است؛ UI ضبط را در ۵۰ ثانیه پایان می‌دهد. محدودیت واقعی فایل و مدت در سرویس هم اعمال می‌شود.

این API **TTS، WebSocket، متن موقت، full-duplex یا cancel** ندارد. رابط آزمایشی مرورگر در README سرویس از Web Speech API هم صحبت می‌کند؛ Sellora از آن مسیر یا سرویس جایگزین استفاده نمی‌کند و فقط دو endpoint فایل مستند را فراخوانی می‌کند.

## انتخاب نشانی و احراز

فایل Deploy Address.txt صریحاً development=`172.20.3.81:30089` و production=`172.20.4.81:30081` است. README ارسالی آدرس‌های قدیمی 30053/30062 را «previous» نامیده؛ از آن‌ها استفاده نشده است. HTTP طبق uvicorn plain نمونه انتخاب شده و باید با ورودی استقرار شرکت تأیید شود. `STT_BASE_URL` سمت سرور قابل تغییر است؛ هیچ نشانی از کاربر HTTP دریافت نمی‌شود و redirect دنبال نمی‌شود.

در app.py ارائه‌شده، احراز API یا header اختصاصی تعریف نشده است. Adapter توکن ساختگی نمی‌فرستد. اگر reverse proxy شرکت احراز دارد، قرارداد header و تزریق امن باید جداگانه ارائه شود. SSL verification فعال است؛ trusted-host و مخزن داخلی با دورزدن TLS از Dockerfile ضمیمه کپی نشده‌اند.

## جریان نوبت

۱. اقدام کاربر، اطلاع پردازش و اجازه میکروفون؛ هیچ ضبط خودکاری پیش از اقدام انجام نمی‌شود.
۲. MediaRecorder با codec قابل پشتیبانی مرورگر؛ echo cancellation و noise suppression در حد قابلیت دستگاه.
۳. توقف دستی یا سقف ۵۰ ثانیه، بستن میکروفون و ارسال blob به `/api/voice/transcribe` خود Sellora.
۴. بررسی نشست، پسوند، حجم و شناسه نوبت، سپس تماس سرور با سرویس شرکت.
۵. متن نهایی در کادر قابل اصلاح قرار می‌گیرد. اگر کاربر در حین پردازش متن تازه‌ای تایپ کرده باشد، گفتار در بخش جدا ظاهر می‌شود تا متن تایپ‌شده از بین نرود.
۶. فقط ارسال متن تأییدشده به `/api/turn` منطق مشترک سفارش را فعال می‌کند. هیچ transcript موقت/نهایی خودبه‌خود سفارش نمی‌سازد.

لغو، generation محلی را افزایش داده، fetch را abort و نتیجه نوبت را در سرور باطل می‌کند. پاسخ قدیمی نمی‌تواند ورودی یا سبد تازه را تغییر دهد. API بالادستی cancel ندارد، پس پردازش آن ممکن است تا timeout ادامه یابد؛ ادعای توقف موتور نمی‌شود. دکمه «لغو صوت» سبد را پاک نمی‌کند.

## خطا و حالت‌ها

مدیر Auto/Online/Offline را انتخاب می‌کند. هر درخواست حالت ثابت همان لحظه را نگه می‌دارد. Auto ابتدا آنلاین، سپس فقط در خرابی شبکه، timeout، پاسخ ناسازگار یا 5xx/429 مسیر آفلاین را امتحان می‌کند. در حالت Online خطا پنهان نمی‌شود. در Offline اصلاً آنلاین فراخوانی نمی‌شود. ورودی نامعتبر، سکوت و مجوز 401/403 fallback نمی‌شوند.

دو circuit مستقل پس از دو شکست وابستگی برای سی ثانیه باز می‌شوند. پس از مهلت فقط یک درخواست آزمایشی در هر مسیر وارد می‌شود؛ موفقیت مدار را می‌بندد. هیچ retry نامحدود وجود ندارد. timeout پیش‌فرض آنلاین ۴۵ و آفلاین ۱۲۰ ثانیه است. هر نشست حداکثر ده نوبت در دقیقه و چهار نوبت درحال‌پردازش در کل نمونه مجاز است؛ این‌ها محدودیت‌های نسخه توسعه‌اند، نه جایگزین rate limit سازمانی.

`/api/voice/status` در UI سلامت دسترسی، وجود فایل مدل و وضعیت circuitها را بدون IP داخلی نشان می‌دهد. وضعیت health برابر موفقیت تشخیص نیست. وقتی سرویس قطع است، متن، سبد و رسید مستقل باقی می‌مانند.

## شبکه و ویندوز

کاربر وب به IP داخلی متصل نمی‌شود. اگر Sellora روی ویندوز شماست، همان ویندوز باید دسترسی مجاز شرکت/VPN داشته باشد؛ اگر روی سرور است، مسیر سرور باید مجاز باشد. HTTP بین مرورگر و IP غیرlocalhost می‌تواند میکروفون را مسدود کند؛ HTTPS معتبر لازم است. فرمان پیشنهادی دسترسی از **همان سیستم بک‌اند**:

```powershell
Test-NetConnection 172.20.3.81 -Port 30089
Invoke-RestMethod 'http://172.20.3.81:30089/health'
```

این فرمان‌ها بررسی دسترسی‌اند، نه تست دقت گفتار. اگر health پاسخ داد اما آنلاین شکست خورد، اتصال سرویس به Google را بررسی کنید. اگر آفلاین 503 است، فایل مدل، سازگاری CTranslate2 و FFmpeg باید روی **سرویس STT** بررسی شوند. نصب Torch روی Sellora این مشکلات را رفع نمی‌کند.

فایل‌های ارسالی شامل پوشه‌های `stt/`، `static/` و مدل سرویس نبودند؛ بنابراین بسته ارسالی به‌تنهایی سورس کامل قابل راه‌اندازی سرویس STT نیست. Sellora به سرویس موجود متصل می‌شود و بازسازی یا جایگزینی آن را ادعا نمی‌کند.

## آزمون واقعی هنوز لازم

در محیط ساخت، health توسعه پاسخ 403 گرفت؛ شبکه شرکت و موتورهای واقعی آزمایش نشدند. پس از اجرا روی شبکه مجاز، با چند صدای فارسی کنترل‌شده شامل شماره موبایل، نام، آدرس، چند قلم و اصلاح تعداد، endpointها و PDF را بررسی کنید. زمان پایان ضبط تا متن با زمان پردازش موتور فرق دارد؛ تأخیر واقعی، دقت، آفلاین، بازگشت اتصال و دسترسی دستگاه باید با سرویس واقعی اندازه‌گیری شوند.
